Data Cleaning and Validation

The Wikipedia table contained repeated header rows, footnote markers, and numeric values stored as character strings. I removed the repeated headers and unnecessary columns, cleaned the text, and converted reserve values and reporting dates into appropriate formats.

Also, I identified an invalid reporting date for Albania (31 Apr 2024). Since April has only 30 days, the date could not be converted into a valid date. I retained the original value for reference and treated the converted date as missing (NA) rather than making an unsupported correction.

Alternative Wikipedia Table: NHL Teams

I applied the same web scraping approach to the “List of teams” table on Wikipedia’s National Hockey League page. The table contained 32 teams and 11 variables, including conference, division, team, city, arena, capacity, founding year, and other organizational characteristics.

Unlike the foreign exchange reserves table, the NHL table did not require removing repeated header rows. However, the cleaning code needed to be modified because the column names and variable formats differed. I changed the column names and converted arena capacity, founding year, and joining year into numeric variables.

After cleaning, the dataset contained 32 observations with no missing values or duplicate teams. All four divisions contained eight teams each. This demonstrates that even when the same html_table() function works across webpages, the data cleaning process must be adjusted to accommodate differences in table structure.

Comparison of Wikipedia and World Bank Data

The Wikipedia and World Bank datasets report the same general concept of total foreign exchange reserves. However, they differ in their reporting periods, country naming conventions, and data collection methods.

The Wikipedia table includes observations from different reporting dates, while the World Bank comparison uses annual observations from 2024. Therefore, differences between the reported values may reflect changes over time rather than accuracy problems between the two sources.

In addition, some countries could not initially be matched because the two datasets used different country names. Country names were standardized where possible to improve comparability.

When Is Web Scraping Appropriate?

Web scraping is appropriate when the required data are publicly accessible on a webpage but are not available through an API or another structured, machine-readable source. However, when an official API is available, it is generally preferable because it offers a more consistent and reproducible method of data collection.

4. Data Plan: Web Scraping TDCJ Correctional Facility Information

Data Source

This study will examines the spatial relationship between correctional facility proximity and county-level crime rates in Texas. Facility information will be collected from the official Texas Department of Criminal Justice (TDCJ) Unit Directory. The directory provides facility names, administrative regions, facility types, cities, and counties, while individual facility pages provide more detailed information, including physical addresses and operational characteristics. This official source is preferred over third-party databases because it provides information directly maintained by the responsible state agency.

Robots.txt and Terms of Service

Before scraping, the website’s robots.txt file will be checked using the robotstxt package in R. The current file does not list the Unit Directory among its disallowed paths. The website’s applicable terms and policies will also be reviewed to ensure compliance with restrictions on automated access and reuse of information. Data collection will be limited to publicly accessible facility information, with attribution to TDCJ and the retrieval date documented.

API Availability and Scraping Justification

No publicly documented API providing the required facility-level information was identified for the TDCJ Unit Directory. Although the website provides structured listings of correctional facilities, detailed information is distributed across individual webpages. Therefore, web scraping using the rvest package is appropriate for collecting and consolidating facility information into a single dataset. If a suitable official API or downloadable dataset becomes available, it will be preferred over scraping.

Data Volume, Rate Limiting, and Caching

The collection will focus on correctional facilities in TDCJ Region II, with potential expansion to other regions for broader geographic comparisons. The scraper will first collect facility names and links from the Unit Directory, then visit individual facility pages to extract addresses and relevant characteristics. Requests will be sent sequentially with a delay of approximately one to two seconds between requests to minimize server load. Retrieved information will be stored locally as CSV files, including the source URL and collection date, to avoid repeated requests during data cleaning and analysis.

Website Changes and Data Validation

Changes in HTML structure, element names, or page layouts may cause the scraper to miss or incorrectly extract information. In particular, extraction methods relying on fixed XPath expressions may fail when webpage structures change. To identify these problems, the collected dataset will be checked for missing addresses, duplicate facilities, unexpected changes in record counts, and inconsistent variable formats. Selected records will also be manually compared with the original TDCJ webpages. These procedures will improve the transparency and reproducibility of the data collection process.
